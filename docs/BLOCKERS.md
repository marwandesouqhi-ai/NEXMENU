# Blockers & Action Items Requiring User Input

This document tracks items that require external resources, real production credentials, or user actions.

| Item | Status | Action Required from User | Exact Command / Steps |
|---|---|---|---|
| **Local PostgreSQL / Docker for Clean SQL Run** | WRITTEN, NOT RUN LOCALLY | Docker daemon is stopped and psql CLI is not installed in the Windows host environment. | 1. Start Docker Desktop.<br>2. Run `docker run --name nexmenu-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:17`<br>3. Apply schema: `docker exec -i nexmenu-pg psql -U postgres < supabase/complete_setup.sql`. |
| **Dedicated Supabase Test Project for `pnpm test:rls`** | WRITTEN, NOT RUN LOCALLY | A dedicated staging/test Supabase project is needed to run live RLS multi-tenant assertions (safety guard blocks running against production). | 1. Create a free test project in Supabase.<br>2. Apply `supabase/complete_setup.sql`.<br>3. Set in `.env`: `RLS_TEST_SUPABASE_URL=https://<test-id>.supabase.co` and `RLS_TEST_SUPABASE_ANON_KEY=<test-key>`.<br>4. Run `pnpm test:rls`. |
| **Lighthouse CI on Windows Local Machine** | CONFIGURED IN CI, BLOCKED LOCALLY | On the Windows local machine, child process pipe buffering in LHCI timed out during local preview socket synchronization. Configured to run automatically in Linux CI (`.github/workflows/ci.yml`). | 1. CI runs automatically via GitHub Actions on Ubuntu runner.<br>2. To test locally: open Chrome DevTools > Lighthouse tab on `http://localhost:4173` while `pnpm preview` is running. |
| **Production Supabase Migration & Super Admin Bootstrap** | ACTION REQUIRED BY OWNER | Apply updated migrations (including 008) to production Supabase project and bootstrap first super admin. | 1. In Supabase Dashboard > SQL Editor, execute `supabase/complete_setup.sql` (or migration `008_super_admin_bootstrap_and_menu_fix.sql`).<br>2. Run bootstrap query:<br>`UPDATE public.profiles SET platform_role = 'SUPER_ADMIN' WHERE email = 'marwandesouqhi@gmail.com';`<br>3. Verify:<br>`SELECT id, email, platform_role FROM public.profiles WHERE platform_role = 'SUPER_ADMIN';` |
| **Dual Vercel Projects & Supabase Auth Redirects** | ACTION REQUIRED BY OWNER | Set up two Vercel projects (Public App on root domain, Admin Panel on `admin.` subdomain) and register both origins in Supabase Auth. | 1. Create Project 1 (`nexmenu-public`): set `VITE_APP_TARGET=public`, domain `yourdomain.com`.<br>2. Create Project 2 (`nexmenu-admin`): set `VITE_APP_TARGET=admin`, domain `admin.yourdomain.com`.<br>3. In Supabase Dashboard > Authentication > URL Configuration, add both origins to **Redirect URLs**: `https://yourdomain.com/**` and `https://admin.yourdomain.com/**`. |
